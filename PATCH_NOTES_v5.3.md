# AQUISET v5.3 — Format fix (Dart 3.13.7, the CI version)

## What this is
`lib/` and `test/` from v5.2, reformatted with **Dart 3.13.7** — the exact
Dart version bundled with Flutter 3.47.9, which is what GitHub Actions uses
(`FLUTTER_ROOT: stable-3.47.9-x64` in the CI log).

## Why it was needed
CI failed twice on the `dart format --set-exit-if-changed` step:
- Run #1: 31 files, 28 changed.
- Run #2 (after formatting on the PC): 31 files, 18 changed.

The PC Flutter is older than CI's 3.47.9, so its formatter writes different
layout. Formatting on the PC can never match CI. This patch was formatted
here with Dart 3.13.7, and the exact CI check was run against it:

```
dart format --output=none --set-exit-if-changed lib test
Formatted 30 files (0 changed)   <- exit code 0, the gate passes
```

(The 31st file in CI is `test/widget_test.dart`, generated by
`flutter create` in CI and already formatted.)

## What changed
Whitespace and trailing commas only — verified file by file against v5.2
(no logic, identifiers, strings, numbers, or theme changed).

## How to apply (on the PC, PowerShell)
1. Download this zip to Downloads.
2. Extract it OVER the project folder (it only replaces `apps\mobile_flutter\lib`
   and `apps\mobile_flutter\test`):

```powershell
Expand-Archive -Path "$env:USERPROFILE\Downloads\AQUISET_v5.3_FormatFix_Dart3137.zip" -DestinationPath F:\ZTECHX\AQUISET -Force; cd F:\ZTECHX\AQUISET; git add -A; git commit -m "Format code with Dart 3.13.7 (CI version)"; git push
```

3. Check the Actions tab. The format step should now pass, then `flutter analyze`
   and `flutter test` run for the first time. If either of those goes red, send
   the failed step log — that is the next error to fix, if any.
4. Do NOT tag v0.1.0 until CI is green.
